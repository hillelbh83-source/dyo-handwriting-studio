דיו — סטודיו לכתב היד שלך

מהאות הראשונה ועד למסמך שלם בכתב שלך. מציירים אותיות, מוסיפים להן גרסאות טבעיות, ויוצרים מסמכים בעברית, באנגלית ועם משוואות מתמטיות. אפשר להוריד PDF או פונט להתקנה במחשב.

מתשובה של AI ל־PDF בכתב יד: בקשו מה־AI לכתוב בפורמט Markdown ‏(MD), העתיקו את המקור לתיבת הטקסט בלשונית מסמך, בדקו את התצוגה ולחצו הורדת PDF. אין צורך בקובץ ביניים או בכלי המרה נוסף. להוראות ולנוסח בקשה מוכן להעתקה.

בחרו את שפת המדריך: English — full guide · עברית

ממשק הסטודיו בעברית. אחרי הפעלתו, אפשר לקרוא את המדריך גם בעמוד מקומי נוח לקריאה, עם בחירת שפה וניווט בין הפרקים.

1. המסמך הראשון שלכם

לא צריך לצייר אלפבית שלם כדי להתחיל.

  1. הפעילו את הסטודיו ופתחו את http://localhost:5173.
  2. בחרו אות מתוך הספרייה בלשונית מעבדת אותיות, וציירו אותה על המשטח עם השורות.
  3. לחצו שמירת גרסה +. ציירו עוד גרסה ושמרו גם אותה.
  4. עברו ל־מסמך והקלידו מילה קצרה עם האות שציירתם. ציירו גם את שאר אותיות המילה כדי שכולה תופיע בכתב שלכם.
  5. התאימו את גודל ועובי טקסט, ואז לחצו הורדת PDF.
  6. הורידו גם גיבוי אותיות וגם שמירת טקסט כדי שיהיו לכם עותקים שאפשר לערוך בעתיד.

רוצים להתנסות לפני שמציירים? הורידו את ספריית כתב היד לדוגמה כ־JSON וטענו אותה דרך טעינת גיבוי. אפשר להוריד בנפרד פונט TTF לדוגמה להתקנה. אלו קובצי דוגמה, ולא כתב היד האישי שלכם. טעינת גיבוי מחליפה את ספריית האותיות הנוכחית, לכן הורידו קודם גיבוי משלכם.

2. הורדה והפעלה

מה צריך?

מחשב עם Node.js בגרסה 22.13 ומעלה, דפדפן מודרני ועותק של הפרויקט. להפעלת הסטודיו המקומי אין צורך בחשבון, במפתח API, בשירות ענן או בהתקנת תלויות של הפריימוורק. צריך אינטרנט להורדת הפרויקט ו־Node.js; אחר כך הספריות נטענות מהמחשב.

אפשרות א — הורדת ZIP

  1. פתחו את הפרויקט ב־GitHub ובחרו Code → Download ZIP.
  2. חלצו את הקובץ לתיקייה רגילה. אל תפעילו מתוך קובץ ה־ZIP עצמו.
  3. פתחו מסוף בתיקייה שחולצה, שבה נמצא package.json. ב־Windows אפשר להשתמש ב־PowerShell; ב־macOS או Linux פתחו Terminal.
  4. הריצו:
npm run dev
  1. השאירו את חלון המסוף פתוח ופתחו בדפדפן http://localhost:5173. כדי לעצור את השרת לחצו Ctrl+C במסוף.

אפשרות ב — שימוש ב־Git

git clone https://github.com/hillelbh83-source/dyo-handwriting-studio.git
cd dyo-handwriting-studio
npm run dev

הגדרות שימושיות

כברירת מחדל השרת זמין גם ברשת המקומית. כדי להגביל את הגישה למחשב בלבד, ב־macOS או Linux:

HOST=127.0.0.1 npm run dev

ב־Windows PowerShell:

$env:HOST="127.0.0.1"
npm run dev

אם פורט 5173 תפוס, ב־macOS או Linux הריצו PORT=5174 npm run dev. ב־PowerShell הגדירו $env:PORT="5174" לפני npm run dev. פתחו את הכתובת עם הפורט המתאים. שינוי כתובת או פורט פותח אחסון דפדפן נפרד; הורידו גיבוי ואת הטקסט לפני המעבר.

מסמך מקלידים או טוענים טקסט, מעצבים, צופים בתוצאה ומורידים PDF.
פונט בוחרים שם ומורידים פונט TrueType להתקנה.

מדריך למשתמש פותחים את המדריך ובוחרים עברית או אנגלית.

מונה התווים המוכנים מציג כמה תווים קיבלו לפחות גרסה שמורה אחת. אפשר לעבוד גם עם ספרייה חלקית ולהוסיף אותיות לפי הצורך.

4. ציור אותיות וגרסאות

בוחרים ומציירים

בחרו קבוצת תווים: עברית, אנגלית קטנה, אנגלית גדולה, מספרים ופיסוק, סימנים מתמטיים או תווים שהוספתם. לחצו על התו הרצוי וציירו בעכבר, באצבע או בעט מגע.

קו הבסיס הכחול הוא הקו שעליו יושבות האותיות הרגילות. השתמשו בקו גובה גוף האות לעיקר הצורה; אותיות יורדות יכולות לעבור מתחת לקו הבסיס. התאמת גובה אוטומטית מתאימה את הציור לסוג התו ושומרת על היחס בין הרוחב לגובה. אפשר לבטל אותה אם מעדיפים את המיקום המקורי.

  • ביטול קו מסיר את הקו האחרון שציירתם במשטח.
  • ניקוי מנקה את המשטח הנוכחי; הגרסאות השמורות נשארות בספרייה.
  • עובי עט משנה את העט שבו מציירים.
  • שמירת גרסה + מוסיפה את הציור לתו שנבחר.
  • התו הבא שחסר בוחר תו שעדיין לא צויר בקבוצה הנוכחית.

שמרו לפני שבוחרים תו אחר. מעבר בין תווים מנקה את המשטח. ציור הופך לגרסה בספרייה רק אחרי לחיצה על שמירה.

מוסיפים אופי לכתב

התחילו מגרסה אחת לכל תו שאתם צריכים. בהמשך מומלץ להוסיף 3–5 גרסאות כדי לקבל שונות טבעית. ההבדלים הקטנים מועילים: כל הופעה של התו באתר יכולה להשתמש בגרסה שמורה אחרת. המחוון אופי כתב היד במסמך משנה את התנועה הטבעית; רענון התצוגה עשוי לבחור גרסאות חדשות.

לחצו על גרסה שמורה כדי לערוך אותה, ואז על עדכון גרסה כדי להחליף אותה. ליצירת גרסה נוספת במקום לעדכן, נקו את המשטח וציירו מחדש. לחיצה על × מוחקת את הגרסה השמורה. בספרייה גדולה מופיעים כפתורים למעבר בין דפי גרסאות.

מכווננים ומוסיפים תווים

המחוונים גודל ו־גובה בשורה משנים את כל הגרסאות של התו שנבחר. איפוס הכוונון לתו הזה מאפס רק את ההתאמות האלה. הציורים המקוריים נשמרים.

כדי להוסיף תו, הזינו תו יחיד בשדה תו נוסף ולחצו הוספה. לקווי שבר אישיים לחצו ציור קו שבר, ציירו קו אופקי ושמרו גרסה אחת או כמה גרסאות.

5. כתיבה ועיצוב מסמך

בלשונית מסמך אפשר להקליד או להדביק טקסט, או לבחור טעינת מסמך ולפתוח קובץ .txt או .md. גודל הקובץ המותר הוא עד 1 MB. טעינת קובץ מחליפה את הטקסט בעורך, לכן שמרו קודם את הטקסט הנוכחי.

התצוגה מתעדכנת תוך כדי הקלדה. רענון תצוגה בונה אותה מחדש ידנית. מסמך לדוגמה — כל התווים עוזר לזהות חוסרים בספרייה; לפני החלפת טקסט קיים שאינו הדוגמה מופיעה בקשת אישור.

הופכים תשובה של AI למסמך PDF

כדי להפוך סיכום, הסבר, שיעור או טקסט אחר שיצר AI למסמך בכתב יד, בקשו ממנו לכתוב בפורמט Markdown ‏(MD). לאחר מכן פשוט מעתיקים את המקור לדיו. אין צורך ליצור או להעלות קובץ .md קודם.

  1. מבקשים Markdown. השתמשו בנוסח שבהמשך והחליפו את הנושא שבסוגריים בבקשה שלכם.
  2. מעתיקים את מקור הטקסט. אם ה־AI מציג אותו בתוך בלוק קוד, השתמשו בכפתור ההעתקה של הבלוק. העתיקו רק את תוכן המסמך, ללא שלושת סימני ה־backtick שעוטפים אותו וללא דברי הפתיחה של ה־AI.
  3. מדביקים בדיו. עברו ללשונית מסמך והדביקו בתיבה הטקסט שלכם. שמרו טקסט קיים לפני שמחליפים אותו.
  4. בודקים את התצוגה. דיו מעצב את הכותרות, הפסקאות, הרשימות, הטבלאות והנוסחאות הנתמכות, ומשתמש בכתב היד ששמרתם כאשר הוא זמין. אפשר להתאים גודל טקסט ועובי דיו לפי הצורך.
  5. מורידים PDF. לחצו הורדת PDF, ואז פתחו את הקובץ ובדקו את העמודים לפני שיתוף.

נוסח בקשה מוכן להעתקה:

כתוב [הנושא או הבקשה שלכם] כמקור Markdown ‏(MD), שאוכל להדביק
בסטודיו לכתב יד דיו. השתמש בכותרות ברורות, בפסקאות קצרות וברשימות
או בטבלאות פשוטות לפי הצורך. למתמטיקה השתמש ב־LaTeX:
$...$ לנוסחה בתוך שורה, ו־$$...$$ לנוסחה בשורה נפרדת.
החזר רק את תוכן המסמך, ללא הקדמה וללא שלושה סימני backtick
שעוטפים את התשובה. אל תשתמש ב־HTML או בתמונות חיצוניות.

Markdown אחראי לעיצוב; ספריית האותיות ששמרתם אחראית לכתב היד. אם חסר תו, ציירו אותו במעבדת האותיות. בדקו את תוכן ה־AI ואת התצוגה לפני ייצוא, במיוחד בטבלאות רחבות או בנוסחאות ארוכות. לחצו שמירת טקסט אם תרצו גם עותק Markdown שאפשר לערוך בהמשך.

מעצבים טקסט בעצמכם

אפשר לכתוב טקסט רגיל. Markdown הוא טקסט עם סימנים פשוטים לעיצוב:

# המחברת שלי
## כותרת קטנה יותר
זהו טקסט **מודגש**, וזו *הדגשה נוספת*.

- פריט ראשון
- פריט שני

1. שלב ראשון
2. שלב שני

| נושא | הערות |
| --- | --- |
| תרגול | קצת בכל יום |

אפשר לשלב עברית, אנגלית ופסקאות בכיוונים שונים. פתחו גודל ועובי טקסט כדי לשנות גודל, עובי דיו, רווח בין מילים ואופי כתב היד. בדקו את התוצאה בתצוגה; הבחירות משפיעות גם על ה־PDF. אותיות שלא ציירתם עשויות להופיע כטקסט רגיל: הוסיפו אותן במעבדת האותיות.

שמירת טקסט מורידה את המקור כקובץ .md, כולל סימני Markdown ונוסחאות LaTeX. ה־PDF הוא התוצאה החזותית; אי אפשר לטעון אותו בחזרה לעורך הטקסט.

6. מתמטיקה ו־LaTeX

לנוסחה בתוך שורה השתמשו בסימן דולר מכל צד. לנוסחה בשורה נפרדת השתמשו בשני סימני דולר מכל צד:

$x^2 + y^2 = z^2$

$$
\frac{1}{2} + \sqrt{x} = \int_0^1 t^2\,dt
$$

שברים, חזקות, אינדקסים, אינטגרלים, גבולות, מטריצות וסוגריים מותאמים משתמשים בסידור של KaTeX ובכתב היד ששמרתם כאשר הוא זמין. ציירו את האותיות, המספרים והסימנים שבנוסחה דרך סימנים מתמטיים וקבוצות התווים האחרות. לחלק מהסימנים יש התאמה לתו מקביל בספרייה. תווים חסרים עשויים להישאר בצורתם המתמטית הרגילה.

גרסה שמורה של קו שבר מותאמת לרוחב השבר. פונט TTF בפני עצמו לא מסדר נוסחאות; השתמשו בעורך המסמכים וב־PDF למסמכים מתמטיים.

7. הורדת PDF או פונט

מסמך מוכן — PDF

  1. פתחו מסמך ובדקו את התצוגה.
  2. בחרו גודל טקסט ועובי דיו.
  3. לחצו הורדת PDF והמתינו לסיום.
  4. פתחו את הקובץ שהורד ובדקו את העמודים לפני שיתוף או הדפסה.

הייצוא משתמש בצורות כתב היד ובפריסה של התצוגה הנוכחית. מסמכים ארוכים עשויים לקחת יותר זמן ומתחלקים לעמודים; בדקו במיוחד נוסחאות רחבות וטבלאות בקובץ המוכן. אין צורך להתקין פונט כדי לצפות ב־PDF.

כתב היד בתוכנות אחרות — TTF

  1. עברו ל־פונט.
  2. הזינו שם הפונט.
  3. לחצו הורדת פונט TTF.
  4. אם נפתח חלון שמירה, בחרו יעד. אחרת הדפדפן מוריד את הקובץ; מופיע גם קישור הורדת הקובץ המוכן.
  5. פתחו את קובץ ה־.ttf במתקין הפונטים של מערכת ההפעלה והתקינו אותו. פתחו מחדש את תוכנת הכתיבה ובחרו את שם הפונט שהזנתם.

הגרסה הראשונה היא ברירת המחדל לכל תו. הגרסאות הנוספות נכללות כחלופות באמצעות salt, אך התמיכה תלויה בתוכנה שבה משתמשים. ערבוב אקראי קיים באתר; אין להניח ש־Word או תוכנה אחרת יערבבו את הגרסאות אוטומטית. תווים שלא ציירתם לא ייכללו בפונט, ותוכנה חיצונית עשויה להציג אותם בפונט אחר.

8. שמירה, גיבוי ושחזור

העבודה נשמרת בדפדפן הזה ובכתובת המדויקת הזו. ספריית האותיות נשמרת ב־IndexedDB; הטקסט וההגדרות באחסון הדפדפן. אין התחברות ואין סנכרון אוטומטי בין מכשירים. ניקוי נתוני דפדפן, גלישה פרטית, דפדפן אחר או כתובת שונה עלולים לגרום לכך שהעבודה הקודמת לא תהיה זמינה.

מה שומרים? איך? מה כלול?
כתב יד לעריכה גיבוי אותיות → .json גרסאות התווים וכוונון הגודל והגובה של כל תו.
מסמך לעריכה שמירת טקסט → .md הטקסט הנוכחי, עיצוב Markdown ומקור הנוסחאות.
מסמך מוכן הורדת PDF → .pdf עמודים לצפייה, להדפסה ולשיתוף.
פונט להתקנה הורדת פונט TTF → .ttf תווים וחלופות לשימוש בתוכנות תומכות.

גיבוי JSON אינו כולל את טקסט המסמך או את כל הגדרות התצוגה. שמרו גם JSON וגם Markdown. קובץ TTF אינו גיבוי לעריכה בסטודיו, וטעינת פונט TTF אינה נתמכת.

לשחזור, פתחו את הדפדפן והכתובת הרצויים, לחצו טעינת גיבוי ובחרו JSON. הטעינה מחליפה את ספריית האותיות לאחר אישור, ואינה ממזגת ספריות. הורידו קודם גיבוי של הספרייה הנוכחית. אחר כך טענו את ה־.md בלשונית מסמך ובדקו מחדש את הגדרות התצוגה. גודל גיבוי לטעינה הוא עד 20 MB, והוא חייב להיות בפורמט הגיבוי של הסטודיו.

לפני סגירה המתינו לכיתוב נשמר במכשיר שלך בכותרת. אם מופיעה שגיאת שמירה, הורידו מיד גיבוי JSON ושמרו גם את הטקסט.

9. שימוש בטלפון ובטאבלט

  1. הפעילו את השרת במחשב עם הגדרות הרשת הרגילות. השאירו את המחשב ער ואת המסוף פתוח.
  2. חברו את שני המכשירים לאותה רשת Wi-Fi מהימנה.
  3. מצאו בהגדרות הרשת את כתובת ה־IP המקומית של המחשב, למשל 192.168.1.20.
  4. פתחו בטלפון http://192.168.1.20:5173, עם כתובת המחשב האמיתית במקום הדוגמה.
  5. ציירו באצבע או בעט מגע. גללו מחוץ למשטח הציור; בתוכו המגע משמש לציור. הלשוניות בתחתית מעבירות בין המעבדה, המסמך והפונט.

בטלפון, localhost מצביע על הטלפון עצמו. השתמשו בכתובת המחשב. אם האתר לא נפתח, בדקו שהשרת פועל, שהוא אינו מוגבל ל־127.0.0.1, ושחומת האש מאפשרת את החיבור המקומי.

לטלפון יש אחסון דפדפן משלו. כדי להעביר עבודה, הורידו JSON ו־Markdown במכשיר המקורי, העבירו את הקבצים בעצמכם וטענו בטלפון. אין סנכרון אוטומטי.

10. פתרון תקלות

הבעיה מה עושים?
node או npm אינם מזוהים התקינו את גרסת Node.js הנדרשת ופתחו מחדש את המסוף.
package.json לא נמצא פתחו מסוף בתיקיית הפרויקט שחולצה, ולא בתיקייה שמעליה.
EADDRINUSE או פורט תפוס עצרו את השרת האחר או בחרו פורט אחר לפי הוראות ההפעלה. זכרו שהאחסון נפרד לכל פורט.
האותיות שלי נעלמו חזרו לאותו דפדפן ולאותה כתובת. אם נמחקו נתוני הדפדפן, שחזרו מגיבוי JSON.
חלק מהטקסט אינו בכתב יד ציירו את התווים החסרים. בדקו גם אותיות אנגליות גדולות/קטנות, פיסוק וסימנים מתמטיים.
תו גבוה או גדול מדי בחרו אותו במעבדה וכווננו גודל וגובה; בדקו את התאמת הגובה האוטומטית בציור.
ציור שלא שמרתי נעלם שמרו גרסה לפני מעבר לתו אחר. הקווים במשטח אינם נשמרים אוטומטית כספריית אותיות.
נוסחה מציגה שגיאה בדקו זוגות סימני דולר, סוגריים מסולסלים ופקודות LaTeX. התחילו מהדוגמה הקטנה בפרק המתמטיקה.
תצוגה או ייצוא לוקחים זמן נסו מסמך קצר יותר, המתינו לסיום העדכון והימנעו מלחיצות חוזרות על ייצוא. שמרו JSON וטקסט לפני רענון הדפדפן.
אין קובץ אחרי ייצוא בדקו את ההורדות או חלון השמירה בדפדפן. בפונט אפשר להשתמש בקישור לקובץ המוכן.
גיבוי נדחה בחרו JSON של הסטודיו, ולא TTF או PDF. בדקו את מגבלת 20 MB ושמרו את הספרייה הנוכחית לפני ניסיון עם קובץ אחר.
השמירה נכשלה הורידו מיד JSON וטקסט; בדקו מקום פנוי במכשיר והרשאות אחסון של הדפדפן.

לדיווח בGitHub Issues, ציינו דפדפן, מערכת הפעלה, מה עשיתם ומה קרה. צרפו דוגמה קטנה שאינה פרטית או צילום מסך, במקום מסמכים אישיים.

npm run docs:build

בריפו נשאר גם שלד React/Vite/Cloudflare. פקודות הבנייה וה־lint של הפריימוורק מיועדות לשלד הזה ואינן נדרשות לשימוש בסטודיו המקומי. לעבודה עליו התקינו את התלויות הנעולות באמצעות pnpm install --frozen-lockfile עם pnpm 11.25.0. בשינוי אחסון או תצוגה שמרו על נתוני המשתמש ועל גרסאות כתב היד.

12. ספריות וקרדיטים

הפרויקט כולל KaTeX לסידור מתמטיקה, markdown-it ל־Markdown ו־jsPDF יחד עם svg2pdf.js ל־PDF. קובצי הרישיון של הספריות מצורפים ב־public/vendor/ וב־vendor/.

ציורים ומסמכים שנוצרים בדפדפן אינם מועלים אוטומטית ל־GitHub. הקבצים שב־public/downloads/ הם דוגמאות שנכללו בריפו. שמרו ייצוא אישי מחוץ לתיקיית הריפו אם אינכם רוצים לפרסם אותו.
